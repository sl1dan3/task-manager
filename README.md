# Task Manager

**Pet-проект для портфолио, в котором я показываю навыки разработки на Vanilla JavaScript:** работу с DOM и событиями, организацию кода через ES-модули и классы, управление состоянием интерфейса и сохранение данных в браузере.

**[Открыть демо на GitHub Pages](https://sl1dan3.github.io/task-manager/)**

Task Manager — менеджер личных задач с поиском, фильтрацией, приоритетами и сроками выполнения. Интерфейс на русском языке, визуально вдохновлён Todoist. Приложение работает без бэкенда и регистрации.

Для оформления я использовал собственные SCSS-функции и миксины из `src/styles/helpers`, включая перевод размеров в `rem` и инструменты для адаптивной вёрстки.

В ближайшее время планирую опубликовать отдельный проект на React, чтобы дополнить портфолио и показать навыки работы с компонентным подходом.

## Возможности

- Создание, редактирование и удаление задач через интерфейс.
- Отметка выполнения и возврат задачи в активное состояние.
- Четыре варианта приоритета: без приоритета, низкий, средний и высокий.
- Необязательный срок выполнения и выделение просроченных активных задач.
- Поиск по названию без учёта регистра.
- Фильтры «Все», «Активные» и «Выполненные», работающие совместно с поиском.
- Счётчики по статусам и количество задач в текущей выборке.
- Сохранение задач и выбранной темы в `localStorage`.
- Светлая и тёмная темы; при первом запуске учитывается системная тема.
- Адаптивная вёрстка с выдвижным меню на мобильных экранах.
- Проверка непустого названия при создании и редактировании.

## Технологии и подходы

| Технология           | Применение                                                         |
| -------------------- | ------------------------------------------------------------------ |
| HTML5                | Семантическая разметка, формы, `<dialog>` и `<template>`           |
| SCSS / CSS           | БЭМ, собственные SCSS-хелперы, `rem`, CSS-переменные, медиазапросы |
| JavaScript           | ES-модули, классы, работа с DOM и событиями                        |

Код приложения не использует сторонние JavaScript-библиотеки и фреймворки. npm-зависимости нужны для разработки и проверки исходников.

## Запуск локально

Понадобятся Node.js и npm. Совместимые версии Node.js по требованиям инструментов проекта: `22.22.2+` в ветке 22, `24.15.0+` в ветке 24 или `26+`. Для приведённого ниже способа запуска сервера также нужен Python 3.

1. Скачайте репозиторий или клонируйте его и перейдите в каталог проекта.
2. Установите зависимости и соберите стили:

   ```bash
   npm ci
   npm run build
   ```

3. Запустите статический сервер из корня проекта:

   ```bash
   python3 -m http.server 8000 --bind 127.0.0.1
   ```

4. Откройте [http://localhost:8000](http://localhost:8000).

Вместо Python можно использовать Live Server в редакторе или другой статический HTTP-сервер. Открывать `index.html` напрямую через `file://` не следует: приложение использует ES-модули. Используйте современный браузер; для `crypto.randomUUID()` нужен `localhost` или HTTPS при размещении в интернете.

Для автоматической пересборки SCSS запустите в отдельном терминале:

```bash
npm run dev
```

Эта команда следит только за стилями: HTTP-сервер и автоматическое обновление страницы она не запускает.

## Организация кода

```text
.
├── index.html                 # Интерфейс, формы и шаблон задачи
├── src/
│   ├── js/
│   │   ├── main.js            # Инициализация компонентов
│   │   ├── Tasks.js           # Данные, CRUD, поиск и отрисовка списка
│   │   ├── Tabs.js            # Фильтры по статусам и их счётчики
│   │   ├── ModalTaskCreate.js # Управление окном создания
│   │   ├── ModalTaskEdit.js   # Управление окном редактирования
│   │   ├── BurgerMenu.js      # Мобильное меню
│   │   └── ThemeSwitcher.js   # Переключение и сохранение темы
│   └── styles/
│       ├── blocks/           # Стили отдельных БЭМ-блоков
│       ├── helpers/          # SCSS-функции, миксины и брейкпоинты
│       ├── _variables.scss   # Переменные оформления и тем
│       ├── styles.scss       # Точка входа SCSS
│       └── styles.css        # Скомпилированные стили
├── package.json
├── package-lock.json
└── stylelint.config.mjs
```

`Tasks` хранит состояние списка и связывает формы, поиск, фильтры и хранилище. `Tabs` сообщает об изменении выбранного фильтра через callback. После изменения данных список перерисовывается из HTML-шаблона, а обработчики действий над задачами используют делегирование событий.

Связь JavaScript с разметкой организована через атрибуты `data-js-*`. Названия задач вставляются через `textContent`. При чтении сохранённых данных проверяются JSON и основные поля объектов; изменения состояния применяются после успешной записи в хранилище.

В интерфейсе используются подписи полей, доступные названия кнопок, `aria-pressed` для фильтров, `aria-live` для сообщений и счётчика, видимые стили фокуса и поддержка `prefers-reduced-motion`.

## Собственные SCSS-хелперы и единицы rem

В каталоге [`src/styles/helpers`](src/styles/helpers) собран мой собственный набор SCSS-функций и миксинов. Я разработал его для повторного использования общих приёмов вёрстки и единообразного задания размеров и адаптивных состояний.

- **`rem()`** в `_functions.scss` переводит числовые значения в `rem` с расчётной базой 16 px: `rem(24)` возвращает `1.5rem`. Функция проверяет, что аргумент — число без единиц измерения.
- **`fluid()` и `fluid-text`** позволяют задавать плавно изменяющиеся размеры через CSS-функцию `clamp()`.
- **`square`, `abs-center`, `abs-x`, `abs-y`, `hide`, `show` и `visually-hidden`** объединяют повторяющиеся приёмы оформления и позиционирования.
- **Миксины медиазапросов** в `_media.scss` задают общие брейкпоинты для адаптивной вёрстки.
- **`hover`** учитывает поддержку наведения: для устройств без неё предусмотрен эффект через `:active`.

В стилях использую `rem` для размеров шрифта, отступов и размеров элементов; брейкпоинты также переводятся через `rem()`. Значения в `rem` зависят от корневого размера шрифта. При этом точечные значения, например тонкие границы, могут оставаться в `px`.

Пример использования хелперов:

```scss
@use '../helpers' as *;

.card {
  padding: rem(24);

  @include mobile {
    padding: rem(16);
  }
}
```

## Сценарий знакомства с приложением

1. Создайте задачу с высоким приоритетом и прошедшей датой — появится отметка просрочки.
2. Измените название, приоритет и срок через окно редактирования.
3. Добавьте ещё одну задачу и проверьте поиск по части названия.
4. Отметьте задачу выполненной и переключите фильтры статуса.
5. Обновите страницу — задачи и их состояние сохранятся.
6. Переключите тему и проверьте интерфейс на узком экране.
7. Удалите ненужную задачу.

## Границы проекта

Данные хранятся только в текущем браузере для конкретного адреса сайта. Синхронизации между устройствами, учётных записей и серверной базы данных нет. Очистка данных сайта удаляет сохранённые задачи и тему.

Приоритет и дедлайн отображаются в списке, но не задают автоматическую сортировку. Уведомления о сроках не предусмотрены. Автоматизированные тесты пока не добавлены; команды проверки покрывают SCSS и форматирование, а сценарий выше предназначен для ручной проверки функций.
